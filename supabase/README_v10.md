# 누적 카테고리 월 충전액을 공동 고정지출에 반영

## 적용 순서

1. Supabase SQL Editor에서 `migration_v10_household_envelope_allocations.sql` 전체를 실행한다. 기존 v3 가구 및 envelope_rate_changes 테이블이 필요하다.
2. 프런트엔드를 빌드/배포하고 두 폰에서 새로고침한다.
3. 같은 달을 선택해 고정지출의 누적 월 충전 목록/합계가 동일한지 확인한다. 나/배우자 표시는 로그인 계정에 따라 반대가 된다.

이 변경은 고정지출 테이블에 복제 항목을 만들지 않는다. 기존 누적 카테고리의 기본 충전액과 월별 변경 이력이 유일한 금액 기준이다. 시작 월 전에는 합산하지 않는다. 과거 조회도 해당 월의 충전 설정을 기준으로 표시한다.

개인 카테고리는 가구 구성원별로 각각 합산하고, 공동 카테고리는 항목당 한 번만 합산한다. 기존 경조사가 공동 항목 하나라면 두 사람 몫으로 자동 복제하지 않는다. 각자 20만 원씩인 경우 실제로 각자의 누적 항목이 등록되어 있어야 한다. 이 SQL은 기존 소유권, 거래, 잔액을 변경하지 않는다.

생활 예산/사용액에는 누적 카테고리를 제외한다. 가계 지출에는 월 충전액만 포함하고, 개인 사용/정산은 누적 잔액에만 반영한다. 추가 적립은 개인 잔액에만 반영한다. 분석의 개인 카테고리 필터와 결제수단 내역에서는 실제 거래를 계속 확인할 수 있다.

조회 함수는 인증된 해당 가구 구성원에게 월 충전 설정만 반환한다. 거래, 추가 적립, 누적 잔액의 개인 접근 권한은 변경하지 않는다. 함수가 미적용되거나 조회에 실패하면 공동 총액을 숨기고 재시도 안내를 표시한다.

앱 복귀/온라인 복구 및 화면이 보이는 동안 30초 간격으로 갱신한다. 설정/거래 편집 중에는 갱신을 보류한다. 월 충전액 저장 후에도 다시 조회한다.
